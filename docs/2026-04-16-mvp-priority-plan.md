# 2026-04-16 MVP 수정/개선 우선순위

## 1. 문서 목적

- 오늘부터 상은님이 합류하는 팀 프로젝트 진행 기준을 맞추기 위한 공유 문서입니다.
- 오늘 안에 바이브 코딩 중심으로 `MVP 초안 완성`을 목표로 합니다.
- 아래 항목은 구현 우선순위와 판단 기준을 함께 정리한 초안이며, 작업 중 변경될 수 있습니다.

## 2. 오늘 목표

- 대시보드와 캔버스 모두에서 `핵심 사용 흐름이 끊기지 않는 상태`를 만든다.
- 시각적 완성도보다 `핵심 UX 완성도`와 `모바일 사용성`을 우선한다.
- 사용자가 `마인드맵 생성 -> 노드 추가/수정/삭제 -> 계속 확장`까지 자연스럽게 수행할 수 있어야 한다.

## 3. 우선순위 기준

- `P0`: 오늘 반드시 반영해야 하는 MVP 핵심 항목
- `P1`: 오늘 되도록 반영해야 하는 사용성/완성도 항목
- `P2`: 오늘 시간이 남으면 반영하는 정리/다듬기 항목

## 4. 작업 우선순위

| 우선순위 | 영역 | 항목 | 목적 |
| --- | --- | --- | --- |
| P0 | 캔버스 | 노드가 초안 노드를 중심으로 좌우 양방향으로 뻗어나가도록 배치 구조 수정 | 마인드맵 기본 구조 완성 |

## 5. 영역별 정리

### 대시보드

#### 수정 방향성

- 가독성 개선
- 디자인과 브랜드 디자인 캔버스와 통일

#### 세부 변경

- 쓸모없는 요소 제거
- UX 플로우 개선

#### 구현 메모

- 첫 화면에서 사용자가 해야 할 행동이 바로 보여야 함
- 카드, 버튼, 섹션 간 정보 우선순위를 다시 정리할 것
- 시각 스타일은 캔버스 화면과 완전히 다른 제품처럼 보이지 않게 맞출 것

### 캔버스

#### 수정 방향성

- MindMeister 사용 경험을 참고한 모바일 웹 사용성 개선
- 기본적인 마인드맵 기능(CRUD) 구성 및 UX 개선

#### 세부 변경

- 노드 배치가 초안 노드를 중심으로 좌우 양쪽으로 뻗쳐 나가도록 수정
- 노드 생성 위치가 겹치지 않되 이전 노드 위치에서 멀지 않은 위치에 순서대로 생성되도록 수정
- 모바일 사용 시 키보드가 올라온 상태 기준으로 자식/형제 노드 추가 버튼 등 핵심 액션 보강
- 플로팅 아일랜드 구성요소 간추리기

#### 구현 메모

- 새 노드 생성 규칙은 예측 가능해야 하며, 사용자가 다음 위치를 대략 예상할 수 있어야 함
- 모바일에서는 입력 중 화면 이동, 버튼 가림, 포커스 손실이 최소화되어야 함
- 플로팅 액션은 꼭 필요한 기능만 남기고 우선순위가 낮은 기능은 숨기거나 2차 진입으로 이동

## 6. 오늘 작업 순서 제안

1. 캔버스 P0 항목부터 처리한다.
2. 노드 배치 로직과 모바일 입력 흐름을 먼저 안정화한다.
3. CRUD 흐름을 실제 사용 시나리오로 점검한다.
4. 대시보드 가독성과 UX 플로우를 정리한다.
5. 마지막에 플로팅 아일랜드와 공통 UI를 가볍게 다듬는다.

## 7. 오늘 완료 기준

- 모바일에서 마인드맵 생성과 노드 확장이 끊기지 않는다.
- 노드 추가 시 겹침이 없고, 사용자가 이해 가능한 규칙으로 배치된다.
- 대시보드 진입 후 다음 행동이 명확하다.
- 팀원이 문서만 보고도 오늘 작업 우선순위를 바로 이해할 수 있다.

## 8. 메모

- 오늘은 `완벽한 디자인`보다 `핵심 흐름이 동작하는 MVP`를 우선한다.
- 구조 변경이 큰 항목은 빠르게 결정하고, 시각 디테일은 뒤로 미룬다.
- 구현 중 새 이슈가 생기면 `P0 흐름에 직접 영향이 있는지`를 기준으로 판단한다.
